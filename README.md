# api-auto-tests
Автотесты по тестовому заданию

Здравствуйте! 

Выполнил тестовое задание по автоматизации API внутреннего сервиса. 

Ссылка на репозиторий с кодом: https://github.com/AlexAnisimof/api-auto-tests
Ссылка на интерактивный Allure-отчет: https://alexanisimof.github.io/api-auto-tests/#suites/68ec05feef1ae8c31b8e928c0c420e72

Что было сделано в рамках задания:
1. Архитектура фреймворка разделена на логические слои (AppClient для отправки API-запросов, BaseTest для конфигурации инфраструктуры сетей и AppTest для чистых тест-кейсов).
2. Сценарии сделаны полностью независимыми (атомарными), для каждого теста генерируется уникальный сессионный токен, что исключает конфликты данных при перезапусках.
3. Отчет Allure собран в статическую папку docs и развернут на хостинге GitHub Pages для удобного просмотра без необходимости локальной сборки проекта.

Результаты тестирования:
* Всего реализовано и прогнано 9 тест-кейсов (включая позитивные сценарии, негативные проверки на авторизацию static key, длину и состав токена, а также неизвестные экшены).
* Найдено 8 успешных прохождений и 1 критический дефект (Bug).

Описание найденного бага:
В сценарии отказа внешнего сервиса авторизации (тест testFailedLogin), когда заглушка WireMock возвращает статус 401 Unauthorized, внутреннее приложение полностью падает с ошибкой HTTP 500 Internal Server Error вместо корректной обработки и выдачи JSON с result: ERROR. Ошибка локализована и наглядно представлена в прикрепленном Allure-отчете.
